# 客户端 1.1.8 / 插件 0.2.6：固定微信窗口尺寸

日期：2026-10-25。

> **已被 1.1.9 取代**：本文的“1200×900 逻辑外框尺寸 × DPI”归一化已改为**物理像素**行为，当前实现与验收见 `docs/audit/GEOMETRY_DPI_1_1_9.md`；以下内容保留为 1.1.8 历史记录。

## 行为

geometry 驱动准备朋友圈时，在导航之前恢复微信主窗口，读取所在显示器的工作区与该窗口 DPI，以 **1200×900 逻辑外框尺寸**换算实际像素并居中。只调整微信窗口，不修改显示器分辨率、系统缩放或发布权限。例：100%=1200×900；125%=1500×1125；150%=1800×1350；200%=2400×1800。

工作区包含任务栏等系统保留区域的扣除结果。目标尺寸放不下时明确报错，不改用更小窗口后继续套用旧坐标。调整后最多检查八次，需要连续两次尺寸/DPI 匹配，并确认窗口完整位于工作区，才进行导航。失败不会点击朋友圈入口或发表按钮。

固定尺寸使用 1200×900 profile；非 100% DPI 的点位按比例换算，不按任意未知窗口选择最近 profile。准备后的窗口位置、尺寸、DPI 变化会拦截输入、正文读回和发表，要求重新准备。只读诊断不触发窗口调整。

默认开启 `geometry_normalize_window`；独立执行器高级 JSON 配置支持 `geometryNormalizeWindow: false` 关闭，或在嵌套 `desktopExecutor` 中设置。关闭后沿用旧定位流程。客户端内置 geometry 执行器使用默认开启行为。

实现使用 [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos) 与 [GetMonitorInfoW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmonitorinfow)，通过标准 Windows API 调整主窗口。

## 验证

- 新增 8 项回归：五档 DPI 的固定逻辑尺寸换算、副屏负坐标、工作区不足/未知 DPI 拒绝、调整先于导航、调整未生效不点击、准备后窗口移动拦截、125% profile 选择、诊断不调整、开关校验及 Win32 调用参数替身。
- 执行器 263 项：260 通过、3 跳过；客户端 83 项通过；Node 192 项：191 通过、1 跳过。合计 534 通过、4 跳过。
- 测试使用替身、合成截图与隔离数据，未启动或调整真实微信，未真实发表。DPI 换算与固定尺寸降低了变量，不能替代目标微信版本/主题/显示器环境的实机验收。
- 新版 EXE 保留管理员、同进程与 PerMonitorV2 声明，并使用原本地自签名证书重新签名。包内模块与网页资源一致性、签名与散列记录在 release 中。
