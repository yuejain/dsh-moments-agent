# V2.0 功能复核与接手开发记录

复核日期：2026-10-23。依据：用户提供的《DSH Moments Agent — 完整工程开发总提示词 V2.0》。

## 2026-10-23 续开发及公开发布

- 已发布公开仓库：https://github.com/yuejain/dsh-moments-agent ，MIT 许可并保留上游声明；公开目录独立整理，不含本机历史验收、账号、令牌、聊天记录、截图与数据库。
- 已完成 PNG/JPEG/WebP/GIF 全像素解码和感知哈希，拒绝损坏/多帧图片；统一 edit 接口及人工编辑桥，自动 Provider 不支持编辑时明确拒绝。
- 已接入可选 DSH 多模态语义审核/OCR（默认关闭）；结构化结果严格校验，错误不放行。只有 Mock 证据，真实模型准确性待验收。
- 本地生成已增加节点、内存、CPU/GPU 状态、队列和 HTTP 失败预检；磁盘和 ComfyUI 输出目录权限尚未预检，资源探测不保证模型可运行。
- 修复干净 Windows 未安装微信时安装检测漏返回值；增加无安装/残留注册表回归；桌面测试强制 UTF-8。
- 最新本机验证：核心 126 项（125 通过、1 跳过），桌面 129 项（127 通过、2 跳过），客户端 63 项通过；verify 17 工具通过；tgz 在独立目录仅安装运行依赖后入口自检通过。下文“本轮验证”为 10 月 21 日历史结果。
- 仍未完成：真实微信 prepare/publish/verify、真实审图模型准确性、公开许可图片检索、正式 Codex 文本委派与完整本地资源预检。不能标记 V2 全量完成。

## 结论

**没有全部实现，不能将当前版本标为 V2 全量完成或真实微信发布验收完成。** 本轮直接修改了项目源代码、补充回归测试、重新构建插件和客户端。创作、显式任务配图导入、审核、审批、模拟发布和恢复链路已有可运行实现；真实微信驱动、视觉语义审核及部分扩展能力仍有缺口。

本文件是本轮复核的状态依据。旧报告的“VERIFIED”是历史时点和特定范围的结果，不能代替本轮修改后的实机验收。尤其历史手工点击发表出现“文字未发送”，不等于正式桌面执行器成功发表。

## 本轮发现并修复

| 问题 | 修改与验证 |
| --- | --- |
| 模型拒绝可能仍被判为审核通过 | 明确要求模型 `passed === true`；拒绝、缺少结论、异常和未配置模型均不能通过开启的模型审核；加入来源证据与不可信文本边界 |
| 重写按钮与后端允许状态不一致 | 支持创作/审批阶段重写，保存草稿版本；事务中撤销旧审批、清除旧哈希；准备/发表中的任务禁止重写 |
| 插件未真正隔离专用 Agent | 创建并持久化专用 DSH 会话；绑定人格、模型、工具白名单；普通会话不能调用 moments 工具；恢复失败降级而非擅自换会话 |
| 卸载时后台操作可能访问已关闭数据库 | 停止调度、中止模型请求、等待在途工具/后台任务，再卸载专用会话和关闭数据库 |
| 崩溃后残留中间态 | 启动恢复；PUBLISHING 转 UNCERTAIN；其他已中断准备流程安全终止；不自动补发 |
| 调度可重入，配置未完整接线 | 单飞执行、持久化下次运行时间、概率与随机延迟；等待模型期间再次检查暂停/停止；过期清理 |
| 所有者命令重启后可重放 | SQLite 持久化命令收据；严格校验所有者、当前账号、群聊身份 |
| 长期记忆和人格配置未进入完整用户流程 | 数据库 CRUD、创作上下文、审批反馈记忆；人格和调度管理 API、可操作的客户端表单 |
| 图片门面把 imageTaskId 当成正文 taskId | 显式解析任务关系；修复 Provider 名称映射；真实 PNG 经过素材库、审核、审批的集成回归 |
| 人工桥缺少自动接续 | 创建并通知 `imports/<imageTaskId>/`；扫描明确任务目录，校验格式/任务/状态后导入并恢复审核审批 |
| 图片任务 ID 路径可绕过终态保护 | 以解析后的正文任务复核状态；拒绝对取消等不可变状态导入图片 |
| 发表时可能已进入静默期 | 点击前重检每日上限、最小间隔和静默时段 |
| GUI 找不到按钮时可能点击任意同类控件 | 删除有名称/标识条件时的宽泛控件回退 |
| 客户端代理存在跨站调用风险 | Host/Origin/Sec-Fetch-Site 校验，拒绝跨站请求及 DNS rebinding；令牌仍仅在服务端注入 |
| 内联管理页“验证”仅查看状态 | 改为调用实际的 verify 接口 |
| 打包范围和测试时钟不稳定 | 排除私有客户端配置/临时输出；修正 lockfile 版本；固定测试时钟，避免夜间静默规则导致随机失败 |

## 升级与回退

1. 保持 `PREPARE_ONLY`，停止 DSH 插件和客户端后备份实际 data 目录（SQLite 数据库及 WAL/SHM、素材、配置）；不要在进程写入时仅复制单个数据库文件。
2. 本机已直接更新源码及 dist。已安装 profile 通过 Junction 指向本项目，但运行中的 DSH 不会因此自动刷新；需要正常卸载/重载插件或重启 Host。
3. 迁移新增所有者命令收据表；不删除已有任务、素材、审批或记忆。
4. 重载后核对 health、工具数、持久化专用会话 ID 和账号；跨会话工具调用应被拒绝。
5. 原 PREPARED 等中断任务恢复时会终止，PUBLISHING 进入 UNCERTAIN。应核查桌面并重新创建任务，不能把恢复当作补发。
6. 回退代码前停止进程；如需回退数据，使用升级前完整备份。重写前版本可以从 draft_versions 查阅，但旧审批已经失效。

## 尚未完成的验收与输入

这些项目不能写作“所有开发完成”：

1. **真实微信执行器**：需要与当前微信版本匹配的可验证控件/视觉识别方案，并用经所有者确认的测试文案执行准备、提交及回读验收。现阶段没有成功发表证据；不能靠无条件坐标点击填补。
2. **完整视觉审核**：语义/OCR 后端已接入 DSH 附件与图像模型消息，需要对真实模型做准确性验收；不能将 Mock 通过视为隐私识别可靠性证据。
3. **图像扩展**：公开许可图片检索、本地磁盘/输出路径预检尚有缺口；自动编辑工作流未接入，当前编辑通过人工桥。
4. **Codex 集成**：正式文本委派、社区图像插件的逐项授权审计和真实能力测试仍未完成；不能将拒绝占位视为自动生图。
5. **升级后 Host 验收**：本轮没有重载用户正在运行的 Host 或真实发微信消息。

后续优先顺序：视觉审核和图片解码 → 图像编辑/来源检索 → 正式子任务适配 → 当前微信驱动校准 → 经批准的实机全链路。
