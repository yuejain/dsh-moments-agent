# 第四轮实机验证：解决微信网络限制 + 真实发布成功 + 4.x 控件测绘

> 时间：2026-10-23 19:30–19:50（Asia/Shanghai）
> 环境：微信 4.1.10.27（WeChatAgent Hook 客户端）、WeChatAgent 0.3.9、DSH 插件 0.2.1
> 账号：`<本机账号已脱敏>`
> 结论：**真实朋友圈已发出**。主因是代理全局模式导致微信 MMTLS/朋友圈连接不可用，切换 FengWo 为「规则」模式并让微信域名直连后，纯文字发布立即成功。

## 1. 网络诊断

现场：

```text
WinINET ProxyEnable = 1
ProxyServer = 127.0.0.1:17980
DNS (FengWoMeta) = 198.18.0.2
FengWoMeta (Meta Tunnel) = Up
FengWo config: mode = "global"
```

- Fake-IP 范围 `198.18.0.0/16`，微信流量全部进入代理 TUN；
- 代理配置为 **全局模式**，连 `qq.com / tencent.com / gtimg.com` 的 DIRECT 规则也不会生效；
- 微信的朋友圈/长连接走 MMTLS，经海外节点容易超时，UI 表现为「文字未发送」；
- 代理断开（直连）时，同一账号的朋友圈内容可以正常加载。

## 2. 修复

在 FengWo 界面把模式从 **全局** 切到 **规则**：

（原始截图保存在本机验收存档，不随公开源码和插件分发。）

规则模式复用已有规则：

```text
DOMAIN-SUFFIX,qq.com,DIRECT
DOMAIN-SUFFIX,tencent.com,DIRECT
DOMAIN-SUFFIX,gtimg.com,DIRECT
```

随后重新连接代理（TUN + 系统代理恢复），微信连接走 DIRECT 路由，
朋友圈刷新正常，发送不再返回“文字未发送”。

建议长期补充：`weixinbridge.com`、`qpic.cn`、`servicewechat.com` 的 DIRECT 规则，
以及 `PROCESS-NAME,Weixin.exe,DIRECT`（如代理内核支持进程规则）。

> 该修改直接写入 FengWo 的运行配置（原模式为 `global`，现为 `rule`）。如需恢复全局模式，
> 在 FengWo 首页把「规则」切回「全局」并重连即可；恢复后微信朋友圈可能重新出现“文字未发送”。

## 6. 限制与风险

- 本次真实发布使用实验性操作器/手工坐标流程，没有接入 `desktop/server.py` 默认发布路径；
- 没有 OCR，无法自动读取编辑器和朋友圈文字，内容核对依赖审批哈希 + 人工截图；
- 几何坐标对 DPI/窗口尺寸敏感，必须用像素检测复核按钮；
- 修改了用户代理模式（全局 → 规则），属于环境变更，需要告知用户；
- 系统测试动态仍在朋友圈，建议所有者手动删除；
- 不要把该流程用于无人值守自动发帖；正式发布仍需一次性审批 + 显式授权。
